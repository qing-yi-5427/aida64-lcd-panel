# PresentMon 指标与曜屏的取舍

2026-10-07，依据官方 v2.6.0 文档与 API。**PresentMon 支持的范围大于本次曜屏接入的范围；2.8.0 已输出显示 FPS、平均显示帧时间与 1% Low。** 以下成本是按事件依赖判断的相对取舍，不是本机实测性能结论。

| 指标 | 用来判断什么 | 曜屏扩展时的要求 |
| --- | --- | --- |
| 显示 FPS | 屏幕收到新帧的频率，含可追踪生成帧 | 本次已接入；无法获取显示数据时为空 |
| 显示帧时间及曲线 | 每帧间隔是否均匀，哪里出现卡顿 | 2.8.0 已增加平均间隔；曲线尚未加入 |
| 1% Low / 0.1% Low | 较慢帧的表现，平均 FPS 难以揭示的短暂卡顿 | 2.8.0 已加入 1% Low：最近 30 秒显示帧间隔取最慢 ceil(1%) 的平均，再换算 FPS；0.1% Low 未加入 |
| 未显示帧数 / 比例 | 提交后被丢弃、没有成为显示帧的比例 | 可复用显示分析结果，需输出分母；不等同于刷新率不足或肉眼卡顿次数 |
| CPU 帧时间、Busy / Wait | 一帧 CPU 阶段的工作/等待节奏 | 扩展现有事件字段；不是整机 CPU 利用率，也不是所有 CPU 核心运行时间之和 |
| GPU Busy / GPU Time / GPU Wait | 显卡处理帧的活跃时长、区间及等待，辅助判断瓶颈 | 要开启 GPU 跟踪，本次关闭；不能只靠这一项断定 CPU 或 GPU 瓶颈 |
| 显示延迟 | 从帧开始到系统报告显示的耗时 | 需传递帧起点和显示事件的关联；不是完整输入延迟或光学响应时间 |
| 点击/输入到显示延迟 | 输入与可见结果之间的时序估算 | 增加输入跟踪，准确性和可用性取决于路径；特定应用/PC 延迟指标需要游戏或驱动标记支持 |
| 应用 FPS、帧类型 | 在支持的路径上区分应用帧、生成帧、重复帧 | 依赖游戏/驱动提供信息；不能承诺任意 DLSS 游戏都能可靠分拆 |
| Animation Error 等平滑性指标 | 动画时间推进与显示节奏的偏差 | 高级分析项，定义和可用字段取决于所选事件/应用时间信息 |
| 呈现模式、允许撕裂、同步间隔 | 判断独占/合成路径及撕裂条件 | 可从已有分析元数据扩展；驱动设置可能覆盖应用请求的同步间隔 |

PresentMon 完整服务/API 还定义 CPU/GPU 温度、频率、功耗、利用率、显存、风扇和性能限制原因等硬件指标，具体可用项取决于硬件、驱动和遥测后端。本次没有引入这套服务与硬件后端；曜屏继续复用既有硬件采集，避免重复监控。

优先建议是帧时间与 1% Low，保持时钟优先、原主题布局及手机现有刷新节奏。若要排查显卡瓶颈，再考虑按需开启 GPU Busy。2.8.0 已按用户选择加入两个较小读数；未默认开启其他跟踪。
