# 曜屏 2.3 验证记录

> 历史记录：以下保留当时的方案、环境与验收状态，不作为当前使用说明或性能结论。当前版本请看 [使用指南](../README.md) 和 [验证记录](../VALIDATION.md)。

日期：2026-09-19。本轮完成手机系统亮度、本次运行 UAC 授权及生成式 PC 图标。以下为 2.3 的结果；后面保留 2.2 的历史记录。

## 本轮完成

- 手机 APK 2.3.0 已实际安装，保留原配对地址与令牌。系统自动亮度设置仍为 1（开启），Activity 实测 `brightnessOverride=-1.0`，说明窗口不覆盖系统亮度。自动亮度数值会随环境变化，不以固定数值不变作为判据。
- APK 忽略旧 PC 的 brightness 字段，PC 2.3 的协议与设置删除该字段。联动模式在亮屏和黑色遮罩状态均使用系统亮度；旧 AIDA64 时段模式自身的亮度设置不受影响。
- 主界面增加“授权完整读取（UAC）”。只有主动点击才启动同一 EXE 的临时提升权限采集进程，采集经本机只读管道发送给普通权限 GUI。主程序退出后取消采集；缩到托盘仍属于本次运行。未增加常驻服务或自动 UAC。
- 73 项自动检查通过：PC/HTTP 26 项、Windows 隔离检查 15 项、Android 规则与数据解析 27 项、网页状态 5 项。新增覆盖移除亮度字段、父进程/创建时间验证、错误会话标识拒绝、父进程退出取消、真实 ACL 管道连续读取以及嵌入图标加载。
- Windows Release 构建通过，0 警告、0 错误；Android 构建及 lint 通过，0 错误、7 项既有警告。
- 使用内置 imagegen 生成透明 PNG，转换为 9 种尺寸的 ICO，并接入 EXE、主窗口、设置窗口、托盘。图标和完整提示词位于 PanelDeck.Desktop/Assets。
- PC 设置页离屏检查完成，没有显示 PC 窗口。未使用 computer use，未触发 UAC，未启动或重启生产 PC 程序。

## 尚未实机验证的范围

本轮没有替用户点击 UAC 按钮，所以真实提权后的传感器结果、Windows 授权取消交互仍待主动使用时验证。隔离测试采用合成读数，不冒充真实传感器结果。权限提升不能让硬件不支持的传感器变成可用值。

手机安装后曾检查到 PC 程序未运行，因此无法验证当时的实际 Wi-Fi 数据流；配对信息保留，手机会自动等待重连。另已确认没有 PC 运行实例后，将原 `artifacts/PanelDeck-Desktop-2.2.0/` 原位更新到 2.3.0，保留原 EXE 路径以复用防火墙规则与快捷方式，没有启动程序。原主程序文件备份在 `artifacts/PanelDeck-2.2-before-2.3/`，独立 2.3.0 目录也保留。两个路径的 EXE SHA-256 一致。

# 曜屏 2.2 验证记录

日期：2026-09-18。最终需求：电脑开机且未睡眠就亮屏；锁屏、静置和游戏不影响亮屏。全部操作未使用 computer use；没有操作 PC 窗口、切换现有 PC 程序、注册服务、修改防火墙或触发 UAC。

## 自动验证

- Windows Release 构建：0 错误、0 警告。
- Android assembleDebug 与 lintDebug 通过，0 错误、7 项警告：固定竖屏、WebView JavaScript、局域网明文 HTTP 与既有手势可访问性提示。Android 12+ 已补充设置数据的备份/换机排除规则。
- 25 项 PC 电源策略、配置与 HTTP/SSE 集成检查：配对到期/单次/次数上限、鉴权、异常请求、手机回执、采样年龄、状态推送与撤销令牌。
- 8 项 Windows 隔离检查：20 次命名管道连接/写入/关闭循环，异常数据、取消连接，以及采集阻塞期间手动息屏、自动恢复、睡眠和恢复联动。全程只使用合成数据和独立回环端口，没有读取真实硬件或操作现有程序。
- 27 项纯 Java 检查：电源状态、45 秒断线缓冲、重连、临时唤醒、局域网地址校验、SSE 完整事件/半包/过长数据及重试上限。
- 5 项网页检查：手机与电脑时钟不同、过期采样与断线分别提示、恢复数据后状态恢复。
- 5 个 PowerShell 脚本语法解析通过。组件配置脚本未执行。
- PC 三页设置使用离屏 DrawToBitmap 检查，未显示窗口。原生下拉框文字未被离屏绘制捕获，另以程序断言确认选中值；真实窗口显示仍待用户方便时检查。

## 本机手机测试

在用户允许操作手机后，用 ADB 安装 2.2 测试 APK，连接一个独立的回环测试服务。通过临时 ADB reverse 传输标准 HTTP/SSE，仅作为隔离测试方式，不是产品运行依赖。测试数据明确标为“合成数据”，没有把模拟读数当成真实硬件结果。

- 面板加载、CPU/GPU 合成数据与电量显示正常；缺失指标显示破折号。
- 测试服务发送睡眠状态后，手机进入黑色遮罩，Service 状态为 off；恢复运行状态后回到 on。
- 关闭测试服务后，手机等待宽限期进入 off；重开测试服务后自动重连并恢复 on，没有重启手机 App。
- 兼容模式关闭时，诊断确认持续 CPU 唤醒锁未持有。
- 手机新设置界面实拍检查通过，联动模式已隐藏工作日/节假日等旧规则。
- 为避免与仍在运行的旧 PC 版错配，测试后恢复了备份的原 APK（2.0.0）和全部原设置，并逐项核对一致；移除临时转发，停止测试服务。PC 现有实例未改动。

## 仍需联合验收

- 新 PC 版本与真实家庭 Wi-Fi 的直连、首次配对、Windows 防火墙配置。
- 新采集服务的实际安装、普通权限 GUI 与服务连接；此前旧版提权读到传感器不能替代该项验收。
- 真实 PC 睡眠/恢复及关机/开机：本轮只注入电源状态，不操作游戏中的电脑。
- 手机真正关闭物理屏幕后通过 Wi-Fi 恢复。此次确认了应用黑屏与重连，不把黑色截图当成面板物理关闭。手机系统超时为原值 10 分钟，尝试缩短测试超时被 HyperOS 权限拒绝，未更改系统权限或超时；立即锁屏设备管理员未激活。
- CPU_FAN 暂定映射仍需 BIOS 或准确实测对照，不按最高转速猜测。

## 使用限制

完整采集内含同一 PC 产品的后台服务，需要首次管理员配置；主界面日常普通权限运行。应用不会因采样缺失自动弹 UAC。局域网 HTTP 不提供传输加密，只用于可信内网。电脑尚未登录时 GUI 未运行，不会提供手机连接；可开启登录启动。息屏后的网络恢复还受手机系统节能策略影响。
