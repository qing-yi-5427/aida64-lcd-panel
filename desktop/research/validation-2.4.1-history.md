# 曜屏 2.4.1 验证记录

> 历史记录：以下保留当时的方案、环境与验收状态，不作为当前使用说明或性能结论。当前版本请看 [使用指南](../README.md) 和 [验证记录](../VALIDATION.md)。

2026-09-19。修复用户实际截图暴露的 PC DPI 错位，以及五套手机 CSS 对齐问题。

## 修复

- PC 原因已定位：从 AutoScaleMode.None 改为 Dpi 会清空此前设置的 AutoScaleDimensions，导致几何未缩放、文字按144 DPI放大。现改为先设置模式，再设置96 DPI设计基准，启用 PerMonitorV2。
- 移除系统标题栏。主窗与设置使用自定义顶栏；保留拖动、关闭、最小化、最大化、边缘缩放和工作区最大化。主窗关闭仍缩到托盘。
- 中文统一微软雅黑 UI，主数值使用 Segoe UI Semibold；调整文字行框，清除按钮底层绘制残影，固定设置页输入控件的最小宽度。
- 五套CSS统一功耗、处理器、内存的两列网格和内边距，移除竖排标签轨道。统一数值行高与单位基线；数值和单位作为紧凑组合，单位紧随数值，使用更小字号，间距为设计画布10px（百分号5px）；CPU缺失值不会改变GPU相同行的位置。
- 页面定位改为可见视口内的固定原点，根据 visualViewport 尺寸和偏移适配缩放；主题只改变颜色、字重和装饰。

## 本轮检查

- 98 项真实隐藏窗口检查通过：保留完整窗体与原生句柄，不剥离内容、不修改线程DPI、不手动伪造字体缩放。实际 DeviceDpi=144，检查字号和控件同步缩放、主数值高度、按钮文字宽度、最小窗口、无系统标题栏、边缘命中。生成主窗与三页设置截图。
- 104 项浏览器引擎检查通过：五套主题 × 1200×2608、1080×1920、360×800、800×1500、1600×900；覆盖边界、重叠、三组列线、CPU缺失/GPU正常的单位基线、数值与单位邻近间距及字号层级、100%三位数字，以及125%和150%可见视口缩放。
- 面板行为11项、主题与视口契约76项通过。Android构建和lint成功，0错误、7条既有警告；PC构建0警告。
- APK 2.4.1（versionCode 8）已安装到手机，配对令牌保留；玻璃主题实机截图确认列线与边界。拍摄时PC已经关闭，手机显示真实离线与缺失值，没有造数据。

## 验证边界与对上轮结论的纠正

2.4 的手动离屏字体/几何缩放没有经过真实初始化路径，漏掉了 DPI 基准重置问题；原记录中相关“已修复”不能作为真实窗口正确性的证据。本轮已删除该预览实现，改为与产品相同初始化的隐藏窗体，增加可失败的几何断言。仍没有操作用户的PC窗口、点击UAC或进行跨物理显示器拖动实测。

原生下拉框在隐藏窗口 DrawToBitmap 中不能完整绘制，因此截图不是原生下拉交互的验收。真实窗口拖动、最大化及跨屏DPI仍需正常使用时确认。未改变硬件采集、局域网协议或系统亮度控制。
