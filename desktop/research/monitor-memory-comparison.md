# 曜屏与 AIDA64 / HWiNFO 内存占用对比

审查日期：2026-09-19。范围：本机只读进程检查、曜屏已有测量文件、厂商官方文档及开发者回复。没有启动 AIDA64 / HWiNFO，没有打开 PC 窗口、触发 UAC 或安装软件。

## 结论

**目前可以证实曜屏新架构的基础采集测试显著降低了私有提交内存，但还不能给出它比当前版本 AIDA64 / HWiNFO 更省内存的排名。** 本机检查时两款竞品均未运行；没有同机、同传感器、同运行时间、同统计口径的竞品数据。不能把历史论坛数字或最低系统要求填进实测对比表。

| 对象与状态 | 私有提交内存 | 是否可直接比较 |
|---|---:|---|
| 曜屏 2.4.1，先前后台双进程，含 RTSS 注入环境 | 238.19 MiB（先前约 30 秒观测末值） | 旧版实际部署基线；授权采集状态及运行时长与新测试不同 |
| 曜屏最终候选，普通权限基础采集双进程，6 分钟测试 | 预热后平均 66.61 MiB，范围 56.87–78.20 MiB，末值 76.14 MiB | 已有实测；不是完整授权采集或发布后长期结果 |
| AIDA64，当前版本、同机同配置 | 未实测 | 本机未运行，不为此启动 |
| HWiNFO，当前版本、同机同配置 | 未实测 | 本机未运行，不为此启动 |

上表中新版数据来自 `artifacts/memory-measurements/release-summary.json`、`release-processes.json` 和 `release-basic.json`。最终候选使用生产 GC 配置跑满约 6 分钟，排除前约 30 秒预热，只保留完整双进程的 66 个记录。有效区间为 2026-09-19 09:10:35–09:16:00（约 326 秒），按每个时间点两个进程的 `private` 字节数求和。按进程 CPU 时间差、真实经过时间和 16 个逻辑处理器归一化，整机平均 CPU 占用为 0.0959%。该结果替代先前 3 分钟中间构建的数字。

这组测试工作集合计平均 150.36 MiB。工作集包含可共享的运行库、代码和映射页面；跨进程相加会重复计算共享页。因此它与 66.61 MiB 私有提交都应如实保留，**不能只挑较小的数字当作所有意义上的“内存占用”**。

主程序模块记录没有 RTSS 或 NVML；硬件采集由子进程完成。结果包含 111 条传感器读数及 14 个面板指标槽位。基础权限下 CPU 温度、功耗、频率和风扇等指标仍为不可读，因此不能说这次已验证完整授权后的内存或全部指标。主程序在这 6 分钟内尚未经历首次 GC，私有提交末值高于均值；**这是短时窗口结果，不能称为内存已稳定在 66.61 MiB，也不能排除更长时间的增长**。

## 本机检查结果

只读进程清单包含两个旧版 `PanelDeck.exe`（PID 52332、51904），没有名称匹配 AIDA64、HWiNFO、RTSS 或 RTSSHooksLoader 的进程。PID 52332 的路径仍为 `artifacts/PanelDeck-Desktop-2.4.1/PanelDeck.exe`，两进程开始时间分别为 01:44:15 和 01:44:35。它们不能冒充新构建的运行结果。

没有检查到 RTSS 主进程，不代表已运行进程中旧的注入 DLL 自动卸载。RTSS 关闭后的旧进程内存与全新进程的内存，不能作为纯代码改动的 A/B 对照。

## 官方资料能说明什么

### HWiNFO：有开发者历史数据，但不适合作为当前数字基准

HWiNFO 作者 Martin 在 2011-06-14 的回复中，报告过一次打开传感器窗口的 HWiNFO64 测试稳定约 23.5 MB。该帖没有给出今天所需的完整配置和内存计数器口径，时间也过早。[官方开发者回复](https://www.hwinfo.com/forum/threads/memory-leak.89/)

2012-05-07，作者发布 HWINFO32 3.95 的测试构建，称 Sensors-only 模式优化后应约 11 MB。这是 32 位旧版的特定优化结果；该帖涉及 Windows XP、旧硬件，不能用来声称当前 HWiNFO64 只需要 11 MiB，也不能据此推算曜屏“多几倍”。该讨论的有效启示是精简传感器模式、避免无用扫描和历史留存，而不是照搬绝对数值。[官方开发者回复](https://www.hwinfo.com/forum/threads/sensor-icons-only-in-system-tray-memory-footprint.430/)

2025-03-15，作者明确说明 Gadget Reporting 仅写出启用的值，且值不变化就不重复写；建议只导出必要传感器。这支持曜屏的“只读取需要的数据、没有新数据不重复推送”的优化方向，但不是内存量化证据。[官方开发者回复](https://www.hwinfo.com/forum/threads/high-disk-usage-caused-by-gadget-reporting.10396/)

### AIDA64：未找到可作为当前基准的官方进程占用数据

查询时的 AIDA64 Extreme 官方产品页列出 Windows / CPU 要求和 97.5 MB 安装磁盘空间，没有提供可比的进程内存基准。安装体积不等于运行内存。[官方产品页](https://www.aida64.com/products/aida64-extreme)

官方旧手册的 32 MB 内存、跑基准测试至少 128 MB 属于旧版本最低系统要求，不是 `AIDA64.exe` 私有提交、私有工作集或稳态工作集测量。不能拿“32 MB”与曜屏两进程的私有提交做对比。[官方旧手册](https://download.aida64.com/aida64extreme-manual.pdf)

官方论坛中能搜到用户报告的内存数字及故障案例，但没有足够的版本、位数、传感器配置、运行时长和统计口径；本报告不将网友截图或异常泄漏案例作为竞品基准。

## 后续公平实测的方法

这部分是对比规范，并未在用户游戏期间执行。

1. **固定环境与功能。** 同一台 PC、同一硬件/显卡驱动，明确软件版本和位数；关闭 RTSS 注入；三者均启用所需 CPU、GPU、RAM、主板风扇数据。读不到温度/风扇的基础采集不能代替完整授权采集。
2. **固定频率与窗口。** 采样均设为 2 秒，主界面均隐藏到托盘。额外分别测窗口打开、最小化、手机在线、手机断联；不混合取平均。
3. **固定运行阶段。** 先记录冷启动峰值，预热 5 分钟后记录 10 分钟稳态，再观察至少 1 小时趋势。排除内存压缩、其他程序卸载、权限模式变化等干扰；不通过强制清空工作集制造低数值。
4. **所有必要进程一起算。** 曜屏统计主进程加采集进程；AIDA64 / HWiNFO 同样纳入提供等价功能所需辅助进程。核心采集对比与完整手机展示链路分开报告；HWiNFO 若另外需要转发桥接程序，完整方案不能漏算它。
5. **保留多个内存指标。** 私有提交（Private Bytes）反映进程独占的提交成本；私有工作集反映当下独占驻留物理页；总工作集单列并说明共享页重复。报告均值、中位数、P95、峰值、首末差及进程数。不能拿任务管理器默认“内存”一列与 Private Bytes 混比。
6. **同时约束 CPU 和体验。** 按 CPU 时间增量 / 真实经过时间 / 逻辑处理器数计算整机 CPU；记录采样耗时、丢失/过期读数和推送延迟。不能靠大量漏采、过慢刷新或关闭必要硬件读数来换内存数字。

在上述条件满足之前，最可靠的优化结论是曜屏自身的受控前后对比；竞品的同口径排名保持“尚未测得”。
