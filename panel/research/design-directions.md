# 曜屏手机面板：差异化布局调研

> 历史设计调研：以下记录当时的参考与布局演进，旧版尺寸、数据数量及截图不作为当前规范。九主题当前布局与验证入口见 [主题说明](../THEMES.md)。

调研日期：2026-09-19。范围：桌面支架手机上的本地硬件监控面板，竖屏优先，横屏可读，不增加联网字体、图片、图表库或常驻动画。已阅读现有 `index.html`、`panel.css`、`THEMES.md`，并实际打开以下六份 DESIGN.md。

参考库 [VoltAgent/awesome-design-md](https://github.com/VoltAgent/awesome-design-md) 是社区对网站视觉语言的分析，主要对象是营销网站，并不是各品牌官方原生应用规范。下述布局是针对曜屏自行设计的适配方案；参考文件中的执行指令不作为项目指令，也不直接照搬品牌标志、专有字体或营销素材。

## 当前问题与共同约束

目前五个主题只有颜色、圆角和字体粗细不同，所有主题仍共享两条细长 CPU/GPU 卡片。竖屏可以并列比较，但阅读路径单一，横屏只缩小整张竖版画布，浪费有效面积。设计变化应当触及信息顺序、块尺寸与横屏重排，而不只是换颜色。

- 保留全部现有数据：CPU/GPU 负载、温度、风扇、频率、功耗，RAM/VRAM 容量和使用率；不凭空添加 FPS、历史曲线、总系统功耗或不存在的阈值。
- 每种布局保留连接状态、时间、数据新鲜度。离线后可保留末次读数，但明显标记过期，不能显示为仍在实时更新。
- 不要把 CPU+GPU 功耗称为整机功耗。缺少一个读数也不能悄悄当零相加。
- 主数值紧邻单位作为不可拆分的一组。推荐 `.reading` 用 `inline-flex; align-items:baseline; gap:.08em`，单位 `font-size:.38em`；负载百分号间距 `.025em–.05em`。不要在数值与单位之间使用 `space-between`、`flex:1`、自动外边距。
- 页面按真实 CSS 视口设计。以 390×844 为竖屏样本：边距 16–20，组件间距 10–16，主负载 48–64，次级读数 24–30，单位 11–14，标签 11–13，型号 11–12px。1200px 设计坐标只可作为按比例对应实现，不能把物理像素直接当 CSS 视口。
- 数字使用系统无衬线字体与 `font-variant-numeric: tabular-nums`，中英字体回退完整。数值不做过强负字距。上下行高度根据实际字体计算，禁止通过固定小高度裁切来“对齐”。
- 数值最大值测试包含 `100%`、`1000.0 W`、`9999 RPM`、`9999 MHz`、`128.0 GB`、缺失 `—`、长硬件名。卡片主体 `min-width:0`，读数组合不换行，只有型号允许两行后截断。
- 横屏判定使用方向或宽高比，而不只用宽度：手机横屏 844×390 不应继续缩放竖屏。窄短屏先减时钟、装饰和间距，再调数据字号；不要优先缩小整页到不可读。

## 1. 精密列表 / Precision

参考：[Linear DESIGN.md](https://github.com/VoltAgent/awesome-design-md/blob/main/design-md/linear.app/DESIGN.md)。借鉴近黑背景、克制紫蓝强调、细边与表层色差；不用其营销图像和大段页面留白。

竖屏结构：

```text
连接状态                       时间
DESK / 01                 星期 / 日期
┌ CPU 型号────────────────────────┐
│ 25%       温度 42°C             │
│ 负载      FAN 1 1230 RPM        │
│           频率 4800 MHz         │
│ 功耗 68.4 W ───负载条───────────│
└────────────────────────────────┘
┌ GPU：相同全宽结构───────────────┐
└────────────────────────────────┘
RAM 34.1 GB / 72%   VRAM 22.4 GB / 70%
数据新鲜度
```

两个全宽横向信息块上下排列，左右分工为大负载与紧凑信息清单；比原两列更适合硬件长名称。横屏时 CPU/GPU 块并排，顶部时间缩成单行，RAM/VRAM 成底部横带。

建议色：背景 `#0b0b0f`，表层 `#15151c`，文字 `#f7f8f8`，次字 `#b4b7c2`，强调 `#a5adff`，线 `#30303b`。读数维持白色，只在小标识、细进度条用强调色。

## 2. 碳素矩阵 / Matrix

参考：[IBM DESIGN.md](https://github.com/VoltAgent/awesome-design-md/blob/main/design-md/ibm/DESIGN.md)。借鉴方角、固定网格、细分割线及结构化规格表；深色版本是本项目适配，不声称是文件完整涵盖的 Carbon Gray-100 主题。

竖屏结构：

```text
曜屏                      09:41
CPU 25%                GPU 10%
型号摘要                型号摘要
             CPU            GPU
温度         42°C           46°C
功耗         68.4 W         85.7 W
FAN 1        1230 RPM       1333 RPM
频率         4800 MHz       1845 MHz
─────────────────────────────────
RAM          34.1 GB        72%
VRAM         22.4 GB        70%
连接与数据新鲜度
```

重点是指标为行、设备为列，而非两张独立大卡。每个数值单元格内部仍是紧凑组，不能为了对齐把单位拉开。横屏可变为左侧 CPU/GPU 负载大数，右侧指标矩阵，RAM/VRAM 底部横带。

建议色：背景 `#161616`，交替行 `#222222`，文字 `#f4f4f4`，次字 `#c6c6c6`，强调 `#78a9ff`，线 `#393939`。圆角 0–4px，无阴影。行名宽约 20%，CPU/GPU 各 40%；缺失读数也保留行高。

## 3. 赛道仪表 / Cockpit

参考：[BMW M DESIGN.md](https://github.com/VoltAgent/awesome-design-md/blob/main/design-md/bmw-m/DESIGN.md)。借鉴黑底、工程规格区、强数字层级与极少强调色。半圆负载仪表是本项目的显示设计，不是该文件提取出的真实车载仪表。

竖屏结构：

```text
连接 / 电脑活动                09:41
CPU 型号
          ╭──负载弧──╮
              25%
 42°C      68.4 W      1230 RPM
 频率 4800 MHz
─────────────────────────────────
GPU 型号
          ╭──负载弧──╮
              10%
 46°C      85.7 W      1333 RPM
 频率 1845 MHz
RAM 34.1 GB 72% / VRAM 22.4 GB 70%
```

竖屏上下两段相同仪表，横屏两段并排，负载大数保持屏幕主角。功耗进入所属处理器区，不再占一整行两个卡片。弧可以沿用 CSS conic-gradient 且仅在数值变更时更新；不做扫针动画、光晕呼吸和刻度闪动。

建议色：背景 `#08090b`，表层 `#13171b`，文字 `#ffffff`，次字 `#b9bec4`，CPU `#82cfff`、GPU `#d7e2eb`。红色仅供真实异常状态且须有确定阈值；不复刻 M 品牌三色徽标。底部各组三指标必须使用同一网格起点。

## 4. 纸感日志 / Journal

参考：[Notion DESIGN.md](https://github.com/VoltAgent/awesome-design-md/blob/main/design-md/notion/DESIGN.md)。当前文件分析的是深蓝与粉彩营销页面，这里仅借鉴暖纸表层、分隔线和条目式信息，不能把方案称为官方 Notion 复制品。

竖屏结构：

```text
SATURDAY
09:41                       9月19日
─────────────────────────────────
01  PROCESSOR
CPU 型号
25%                     使用率
温度 42°C       功耗 68.4 W
FAN 1 1230 RPM   频率 4800 MHz
─────────────────────────────────
02  GRAPHICS
GPU 型号
10%                     使用率
温度 46°C       功耗 85.7 W
FAN 1 1333 RPM   频率 1845 MHz
─────────────────────────────────
03  MEMORY
RAM …                   VRAM …
```

无整块卡片包裹，只靠章节序号、横线和文字层级组织。横屏成三章列：CPU / GPU / 时钟+内存，日期不占整行。暗室默认不自动切这个白色主题，保持用户选择；不把主题切换和亮度控制耦合。

建议色：背景 `#f4f1e9`，文字 `#282822`，次字 `#66655e`，线 `#d4d1c7`，强调 `#6c694c`，章号浅表层 `#e8e5d9`。无纸纹位图、阴影或视频。该方案主要追求桌面文具感；浅底不作为省电卖点。

## 5. 大钟积木 / Tiles

参考：[Apple DESIGN.md](https://github.com/VoltAgent/awesome-design-md/blob/main/design-md/apple/DESIGN.md)。借鉴大标题、产品块节奏和轻量分区，非 Liquid Glass；无需背景模糊。

竖屏结构：上方约四分之一是大时钟与日期；下方 CPU 横跨整行、GPU 横跨整行，每块左侧负载，右侧 2×2 温度/功耗/FAN 1/频率；最下 RAM/VRAM 两块。横屏时左侧约 28% 作为大钟与内存侧栏，右侧上下两条 CPU/GPU。用户一眼先读时间，再扫硬件。

建议色：背景 `#101218`，圆角表层 `#222630`，文字 `#f5f5f7`，次字 `#c0c5d0`，CPU `#bbdbff`，GPU `#d8c8ff`。静态明暗边线代替实时模糊，圆角 18–22px。大时钟不能挤压 FAN 和频率，不使用过粗圆润字体。

## 6. 黑白遥测 / Mono

参考：[xAI DESIGN.md](https://github.com/VoltAgent/awesome-design-md/blob/main/design-md/x.ai/DESIGN.md)。借鉴近黑、白色主字、等宽标签、无阴影。不是 Nothing 品牌方案，库中未发现 Nothing DESIGN.md。

竖屏结构：巨大时间下是一条 CPU 全宽遥测记录和一条 GPU 全宽遥测记录，每条先显示 `CPU / 型号`，下一行大负载 `025%`（实现时不必强制补零），余下指标以带短标签的两行紧凑数值显示；底部以大 RAM/VRAM 用量加短横条收束。横屏时以横向三轨排时钟、CPU、GPU，内存贯穿底部。

建议色：`#080808`、`#f3f3ed`、`#b5b5af`、线 `#343434`；只有断连等状态可以出现单点琥珀提示。不靠彩色区分 CPU/GPU，标题与位置必须明确。等宽字体限小标签和日期，读数仍采用较窄系统数字，避免 RPM 变得过宽。

## 实现优先级与验证

建议先实现 Precision、Matrix、Cockpit、Journal 四套，覆盖全宽信息带、交叉矩阵、仪表和编辑式章节四种不同阅读方式；Tiles 可作为现有 glass 的布局升级，Mono 作为额外极简选项。保留原五主题与用户已存主题 ID，新增 ID 不覆盖旧偏好。

共用数据绑定与读数组件，布局只改变信息容器位置和 CSS。不要复制多套 DOM 后全部常驻更新；不得重复同一 ID。可以允许主题切换时改变有限容器结构，或在新布局中使用网格区域，但应保持设备语义与无障碍阅读顺序。

低功耗策略：系统字体；零远程资源；无持续 CSS 动画；无 Canvas/WebGL 背景；无整页滤镜；原值不变不更新 DOM；仅数值更新时改进度条；既有秒钟精度保持，不额外建立每主题定时器。OLED 上深色显示通常更有节能潜力，但这里不保证具体省电比例，也不改变手机自动亮度。

尺寸验证至少覆盖 360×800、390×844、412×915、360×640、800×360、844×390、915×412；真机使用 ADB 实际截图（若可用），不打开 PC 可见浏览器。截图必须覆盖所有新增布局，不应只用 DOM 契约宣称已验证视觉。

静态与视觉检查应验证：所有数值单位间隙一致且不超过约 0.12 倍该数值字号；横屏有实际重排；型号不挤数字；无溢出裁切；失联/缺失/100%/最长 RPM 状态均能看清；主题切换保留实时采集与连接状态。
