# 手机面板主题

九套主题共享同一套本地 HTML 和数据更新逻辑，无远程字体、图片、组件库或网络依赖。原有五套保留双列布局，四套新增主题通过独立 CSS 重排。`window.PanelDeck.setTheme(id)` 返回最终采用的主题 ID；未知值安全回退为 `classic`。初始 URL 可为 `index.html#theme=material`，主题切换不需要重新配对。

| ID | 设置名称建议 | 视觉方向 |
| --- | --- | --- |
| classic | 经典仪表 | 黑色底、琥珀 CPU、蓝色 GPU、清晰仪表分区 |
| material | Material | 深绿调色、浅绿与淡紫强调、圆角色调卡片和胶囊标题 |
| winui | WinUI | 浅灰蓝底、小圆角、克制的边框层级、蓝色与紫色强调 |
| flutter | Flutter 活力 | 浅纸色背景、紫粉分组、大字重、活泼圆角卡片 |
| glass | macOS 玻璃 | 深蓝紫渐变、半透明表层、高光细边、柔和层次 |
| editorial | 纸页 · 数据周刊 | 暖纸色、上下章节和细分隔线；横屏左日期栏、右规格章节 |
| ambient | 静夜 · 桌面时钟 | 大时钟主视觉、下方紧凑硬件条目；横屏左时钟、右硬件 |
| telemetry | 遥测 · 性能座舱 | 深色工业数据轨道，负载主数与规格清单；横屏展成整行 |
| studio | 拼贴 · 硬件工作室 | GPU 大主块、独立功耗块、CPU 横条、非对称内存区 |

Flutter 是 UI 框架，官方默认采用 Material 3，并没有单独的“Flutter 设计规范”。这里的 Flutter 主题是参考其自定义组件和展示常见的活泼卡片风格，避免与 Material 主题重复。

玻璃主题借鉴 Apple 对材质、层次和文字可读性的原则，使用静态 CSS 渐变和边缘高光；不是原生 Liquid Glass。没有 `backdrop-filter`、背景动画或持续过渡，避免面板常驻时反复模糊合成。

## 远距阅读

以 1200px 设计画布计，主要温度 / 风扇 / 时钟数值由原 54px 提高到 86px，常规标签由 23–27px 提高到 33–38px，硬件型号由 18px 提高到 30px。CPU 风扇显示标签始终为 FAN 1；采集数据和来源不改写。使用双行硬件名称，超长内容截断而不挤压数值。

画布高度随竖屏比例调整（2200–3200px），短屏压缩留白、保留全部指标。新增四套横屏采用 2000×1040–1700 设计画布重新编排，切换主题即时重新计算，不缩小整张竖屏界面。原有五套横屏仍等比居中呈现。APK 2.5.0 遵循系统旋转设置，开启系统自动旋转后可使用横屏。

## 2.5.1 双向同步与 PC 预览

PC 的“面板外观”与手机设置共同编辑已保存主题。默认浏览器预览从快照读取 `panelTheme`，显式 `#theme=` 则作为固定草稿；Android 本地页始终由 APK 控制选择，硬件快照不会覆盖临时预览。`preview.html` 仅提供手机比例外框，内嵌原始面板，不维护第二套 CSS。

主题同步复用 SSE，不增加手机轮询。手机的未发送选择持久保存，重连补发；首次迁移由 PC 接纳手机原主题，后续初始化请求只读取当前选择。两个设备离线期间各自保存时，最终以 PC 接收到的保存顺序为准。

## 2.5.0 新布局与选择界面

所有主题都保留完整时分秒、星期和日期；拼贴主题额外标注“当前时间”并放大时钟。底部加入下载/上传网速，14 项硬件指标与 2 项网速均可见。网速使用十进制 B/s、KB/s、MB/s、GB/s 自适应显示，不是 bit/s；数值来自 PC 2.5.0 活动物理网卡汇总（包含局域网）。旧版 PC 尚未发送该字段、首次采样、切换网卡或读数不可用时显示 `—`，不伪造为零。

布局测试扩展为 16 个指标及时间始终可见；包含父容器裁切检测。生成的对比页仍只使用标明的示例数据，不代表手机实际下载速度。

新增主题分别置于 `layout-editorial.css`、`layout-ambient.css`、`layout-telemetry.css`、`layout-studio.css`，所有规则限定在自己的 theme 作用域，保留原有真实数据及缺失、离线标识，不添加伪造曲线或整机功耗。2.6.0 增加实际采集的全屏 FPS 与来源说明，缺失或断线时显示 `—`；共用 `network.css` 的帧率读数样式。帧率位于时钟附近，字号低于时钟；保留九主题原有硬件布局和时钟字号，竖屏从页脚移出的空间用于时钟下方读数，拼贴与遥测横屏使用标题与时钟之间的留白。单位保持基线紧邻，几何数值和缺失占位都经过布局检查。沿用原有更新、暂停、配对和屏幕联动机制，不增加页面定时器。

设计参考来自 [VoltAgent/awesome-design-md](https://github.com/VoltAgent/awesome-design-md) 的社区分析，按手机远距阅读重新设计，并非品牌官方应用规范。具体参考、取舍与来源见 [方向调研](research/design-directions.md)、[纸页与静夜](research/editorial-ambient.md)、[遥测与拼贴](research/telemetry-studio.md)。

手机设置“面板外观”的主题选择改为独立可滚动选择框，每项显示名称、说明和选中状态。选择只预览；保存后持久生效，取消仍恢复原主题。4 秒全屏预览不改变电脑屏幕指令。桌面只读网页也提供四个 CSS 静态文件路由。

`node desktop/render-panel.cjs` 对九主题进行竖屏、横屏、短屏与缩放检查，覆盖正常、缺失、最大值、长型号及离线状态；输出 `artifacts/ui-2.5.0`。`node desktop/render-panel-gallery.cjs` 生成四套方案的离线对比页及总览图，页面使用明确标注的示例数据。

## 验证

`node desktop/test-panel.cjs` 覆盖原有连接、采样超时和恢复合同；`node desktop/test-panel-themes.cjs` 覆盖五套主题选择与回退、更新后主题保留、固定 FAN 1、暂停 / 离线 / 电量合同、画布比例和本地静态资源约束。另以独立无窗口 Edge 渲染五主题在 1200×2608、1080×1920、360×800 下的截图，47 项主题/布局/脚本检查通过；真机检查了经典面板与主题设置。截图见 artifacts/ui-2.4。

## 2.4.1 对齐修复
功耗、处理器、内存使用同一列宽、间距和内边距；数值与单位使用固定行高和基线，删除竖排标签轨道。五套主题在五种尺寸、缺失值/100%读数及视口缩放下通过104项真实引擎检查，新增25项布局契约检查；真机玻璃主题截图见 artifacts/ui-2.4.1。上文2.4截图为历史版本。


## 读数组合间距修正

遵循 frontend-design 对排版层级、分组和留白的要求，数值与单位始终作为一个紧凑读数组合：单位紧跟数值，在 1200px 设计画布上间隔 10px；负载百分号间隔 5px。单位保持较小字号并按基线对齐。数值不再伸展填满整行，因此不会把单位推向卡片右边缘。负载圆环作为独立元素保持在行右侧。

固定行高、缺失值占位高度、卡片列起始线和列间距不变。这次修正仅调整共享读数组件，五套主题一致生效；修改后的真实渲染与真机结果以最新验证记录为准。


## 2.8.0 帧节奏读数

九主题共用原 FPS 表面、配色和圆角。竖屏保持 144px 卡高，左侧主 FPS 为 76px，右侧帧时间与 1% Low 为 44px；时钟及硬件布局不变。Studio / Telemetry 横屏采用 64px 主数与 34px 辅助数的两行排列；Editorial 窄横屏采用主数在上、两个辅助数并列在下，色块高度 204px。无图表、动画或新增前端计时器。

1% Low 标注 30s，不足完整窗口时为 —；竖屏和纸页横屏显示统计中。无数据、断连、过期同时清空三个读数。示例与布局截图使用明确的测试值，不能作为真实游戏测量证据。
